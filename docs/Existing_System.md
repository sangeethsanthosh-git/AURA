# Existing System

Current AI assistants and chatbot tools provide powerful capabilities, but they often depend on cloud-first architectures and closed ecosystems. This creates limitations for privacy, offline access, customization, and research expansion.

## Drawbacks

## Cloud Dependency

Most assistants send user prompts to remote servers. This makes the assistant dependent on external availability, account access, and provider-side limits.

## Privacy Issues

User conversations may include personal, academic, or project-related data. Cloud-first systems can create privacy concerns because sensitive data leaves the local machine.

## Internet Dependency

Many assistants cannot function when the internet is unavailable. This is a serious drawback for an assistant intended to support desktop productivity at all times.

## High Latency

Cloud requests can be delayed due to network conditions, provider load, or API rate limits. Offline local models can reduce latency for routine conversation and local tasks.

## No Offline AI

Many systems lack a real local LLM mode. Without offline AI, the assistant cannot provide basic help when disconnected.

## Limited Multilingual Support

Some assistants provide multilingual support but do not allow local language-specific model routing or speech customization.

## Separate Applications

Users often need separate tools for chat, weather, maps, notes, translation, and coding help. This creates workflow fragmentation.

## No Unified Desktop Assistant

Existing tools are often web-based or mobile-first. AURA targets a desktop assistant experience with local services and future desktop UI integration.

## Limited Customization

Commercial assistants may not expose routing logic, provider selection, logging, or internal modules for research and experimentation.

## Vendor Lock-In

Cloud-only assistants can lock users into one provider. AURA is designed to support multiple AI providers and local fallback.
